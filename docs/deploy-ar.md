# دليل النشر على استضافة

الموقع جاهز للرفع على أي استضافة تدعم PHP 8.3 أو أحدث وقاعدة MySQL أو MariaDB، مثل Hostinger أو cPanel أو VPS.
كل الخطوات تُنفَّذ مرة واحدة فقط، ما عدا الخطوة 5 التي تتكرر مع كل تحديث.

## ما تحتاجه من لوحة الاستضافة

- **PHP 8.3+** مع الإضافات `gd` و`intl` و`pdo_mysql`.
- **قاعدة بيانات** باسم ومستخدم وكلمة مرور.
- **صندوق بريد** على دومينك (مثل `hello@your-domain`)، وبياناته: الخادم والمنفذ واسم المستخدم وكلمة المرور.
  البريد شرط أساسي، لأن كود الدخول للوحة التحكم يصل عليه، وبدونه لا يستطيع أحد الدخول.
- **SSH** (متوفر في Hostinger من «Advanced › SSH Access»).

## 1) رفع المشروع

```bash
cd ~ && git clone https://github.com/m77mdabdo/mohamed-abdo-portfolio.git portfolio
```

اجعل **جذر الموقع** (Document root) هو مجلد `portfolio/public`. إن كانت الاستضافة تفرض `public_html`:

```bash
rm -rf ~/public_html && ln -s ~/portfolio/public ~/public_html
```

## 2) ملف الإعدادات

```bash
cd ~/portfolio && cp .env.production.example .env && nano .env
```

املأ قيم `APP_URL` (بـ https) و`DB_*` و`MAIL_*`. لا ترفع هذا الملف إلى GitHub أبداً.

## 3) التثبيت

```bash
bash scripts/deploy.sh
```

السكربت يثبّت الحزم ويبني الواجهة (أو يستخدم `public/build` المرفوع إن لم يوجد Node) ويُنشئ الجداول.
وفي أول تثبيت يستورد المحتوى الأصلي والصور، ثم يجهّز الكاش، وفي النهاية يعرض فحص الجاهزية.

**لنقل محتواك الحالي من جهازك بدل المحتوى الأصلي** (كل تعديلاتك ومسوداتك ورسائلك):

```bash
# على جهازك
php artisan portfolio:backup        # يُنشئ ملفين في storage/app/private/backups
# ارفع الملفين إلى الخادم، ثم على الخادم:
php artisan portfolio:restore db-....sql.gz --into-main     # يطلب كتابة اسم القاعدة للتأكيد
tar -xzf media-....tar.gz -C storage/app/public
php artisan optimize
```

## 4) حساب المالك والمهمة المجدولة

```bash
php artisan portfolio:create-owner      # بريدك وكلمة مرور تكتبها بنفسك (12 حرفاً على الأقل)
php artisan portfolio:mail-test you@example.com    # تأكد أن البريد يصل قبل أن تحاول الدخول
```

أضف **مهمة Cron واحدة** من لوحة الاستضافة، تعمل كل دقيقة:

```
* * * * * cd ~/portfolio && php artisan schedule:run >> /dev/null 2>&1
```

هذه المهمة تأخذ نسخة احتياطية يومياً الساعة 3:30، وتنفّذ أي مهام في قائمة الانتظار.

## 5) كل تحديث بعد ذلك

```bash
cd ~/portfolio && git pull && bash scripts/deploy.sh
```

السكربت يأخذ نسخة احتياطية قبل أي تغيير في القاعدة، ويضع الموقع في وضع الصيانة فقط أثناء التحديث.

## فحص الجاهزية

```bash
php artisan portfolio:preflight
```

تعني ✗ مشكلة يجب حلها قبل الإعلان عن الموقع، وتعني ! شيئاً يُستحسن إكماله (مثل رفع ملف السيرة).
وفي حال وجود أي ✗ يتوقف الأمر برمز خطأ.

## ما هو مضبوط مسبقاً

- **HTTPS:** يُضاف HSTS تلقائياً، ولا يرد الموقع إلا على نطاق `APP_URL`.
- **الروابط:** كل الروابط في الرسائل تُبنى من `APP_URL`.
- **الضغط والكاش:** ملفات الواجهة والخطوط والصور مضغوطة ومخزنة في المتصفح عبر `public/.htaccess`.
- **مجلد المشروع:** يرفض أي طلب من المتصفح (`.htaccess` في الجذر)، فلا يمكن الوصول إلى `.env` أو السجلات حتى لو وُضع داخل `public_html` بالخطأ.
- **الدخول للوحة التحكم:** كلمة المرور ثم كود من 6 أرقام يصل على البريد، صالح لمدة 10 دقائق ولمرة واحدة.
  الأكواد محدودة بإرسالين في الدقيقة، ومحاولات الدخول محدودة بخمس في الدقيقة.
